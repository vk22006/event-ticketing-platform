# EventPro - நிகழ்வு வாழ்க்கைச் சுழற்சி மற்றும் டிக்கெட் வழங்கலுக்கான முழுமையான தளம்

[English](../README.md) | தமிழ் | [简体中文](README_ZH.md) | [हिन्दी](README_HI.md) | [Bahasa Indonesia](README_ID.md)

EventPro என்பது நிகழ்வின் முழு வாழ்க்கைச் சுழற்சியையும் நிர்வகிக்க வடிவமைக்கப்பட்ட முழுமையான நிகழ்வு மேலாண்மை மற்றும் டிக்கெட் வழங்கும் தளமாகும். ஆரம்பத் திட்டமிடல் மற்றும் வெளியீடு முதல் இருக்கை முன்பதிவு, டிக்கெட் உருவாக்கம், முன்பதிவுக்குப் பிந்தைய மேலாண்மை வரை அனைத்தையும் இது கையாள்கிறது. பங்கேற்பாளர்கள் (Attendees), நிகழ்வு ஏற்பாட்டாளர்கள் (Event Organizers), தள நிர்வாகிகள் (Platform Administrators) ஆகிய மூன்று முக்கியப் பயனர் வகைகளுக்குத் தனிப்பயனாக்கப்பட்ட பணிச்செயல்முறைகளை இந்தத் தளம் வழங்குகிறது.

![முகப்புப் பக்கம்](img/home_page.png)

இந்தக் களஞ்சியம் முழுவதும் **Rust மற்றும் Axum** (`eventpro-rs/`) மூலம் எழுதப்பட்ட, அதிக செயல்திறனும் நினைவகப் பாதுகாப்பும் கொண்ட பின்தளத்தால் இயக்கப்படுகிறது. பழைய Express.js பின்தளம் நிரந்தரமாக நீக்கப்பட்டுள்ளது. சேவையகம் உருவாக்கும் MiniJinja வார்ப்புருக்களை வழங்கும்போது, தரவுத்தளப் பரிவர்த்தனைகளுக்கான கடுமையான எல்லைகள், வரிசை-நிலை pessimistic concurrency locks, மற்றும் வரம்பிடப்பட்ட multipart நினைவகப் பயன்பாடு ஆகியவற்றை இந்தக் கட்டமைப்பு அமல்படுத்துகிறது.

## முக்கிய அம்சங்களும் பயனர் பணிச்செயல்முறைகளும்

### பங்கேற்பாளர்கள் (Attendees)
- **நிகழ்வு பட்டியல் மற்றும் கண்டறிதல்**: வெளியிடப்பட்ட நிகழ்வுகளைப் பார்க்கலாம்; வகை, நகரம், உரைத் தேடல் ஆகியவற்றின் அடிப்படையில் நிகழ்நேர வடிகட்டல்களையும் சேவையகப் பக்கப் பக்கமிடலையும் பயன்படுத்தலாம்.
- **பல நிலை இருக்கைகள் மற்றும் முன்பதிவுகள்**: பொது நுழைவு அல்லது தனிப்பயன் இருக்கை வகைகள் (VIP, Regular, Student போன்றவை) மூலம் டிக்கெட் எண்ணிக்கையைத் தேர்ந்தெடுக்கலாம்; விலை உடனடியாக மறுகணக்கிடப்படும்.
- **பரிவர்த்தனை அடிப்படையிலான முன்பதிவு**: டிக்கெட்டுகள் அணு-பண்புடைய தரவுத்தளப் பரிவர்த்தனைகளுக்குள் முன்பதிவு செய்யப்படுகின்றன. ஒரே நிகழ்வுக்கு அளவுக்கு மீறிய முன்பதிவு நடைபெறாமல் இருக்க வரிசை பூட்டுதல் பயன்படுத்தப்படுகிறது.
- **டிக்கெட் பாஸ்கள் மற்றும் அச்சிடுதல்**: தனித்துவமான எழுத்து-எண் டிக்கெட் பாஸ்களைப் பெறலாம். அச்சிடுதல் அல்லது PDF ஆக ஏற்றுமதி செய்வதற்காக, வழிசெலுத்தல் கூறுகள் நீக்கப்பட்ட தனி அச்சுப் பக்கங்களும் உள்ளன.
- **சுயசேவை ரத்து**: நிகழ்வு தொடங்குவதற்கு முன் முன்பதிவுகளை ரத்து செய்யலாம். ரத்துசெய்தவுடன் நிகழ்வு மற்றும் இருக்கை வகையின் திறன் மீண்டும் உடனடியாகக் கிடைக்கும்.

### நிகழ்வு ஏற்பாட்டாளர்கள் (Organizers)
- **நிகழ்வின் முழு வாழ்க்கைச் சுழற்சி கட்டுப்பாடு**: Draft, Published, Cancelled/Completed ஆகிய நிலைகள் வழியாக நிகழ்வுகளை நிர்வகிக்கலாம்.
- **தனிப்பயன் இருக்கை வகைகள்**: ஒவ்வொரு நிகழ்விற்கும் தனித்தனி இருக்கை வகைப் பெயர்கள், இருக்கைத் திறன், விலை ஆகியவற்றை அமைக்கலாம்.
- **பேனர் ஊடக மேலாண்மை**: உள்ளடக்கத்தை கடுமையாகச் சரிபார்த்து, சீரற்ற கோப்புப் பெயர்களைத் தானாக வழங்கி, நிகழ்வு நீக்கப்படும்போது கோப்புகளைத் தானாகச் சுத்தம் செய்யும் முறையில் பேனர்களைப் பதிவேற்றலாம்.
- **விற்பனை மற்றும் வருவாய் டாஷ்போர்டுகள்**: ஒவ்வொரு நிகழ்விற்குமான மொத்த டிக்கெட் விற்பனை, மீதமுள்ள இருக்கைத் திறன், உருவான வருவாய் ஆகியவற்றைக் கண்காணிக்கலாம்.

### தள நிர்வாகிகள் (Platform Administrators)
- **முழுத் தள நிர்வாகம்**: பதிவுசெய்த பயனர்கள், செயலில் உள்ள ஏற்பாட்டாளர்கள், வெளியிடப்பட்ட நிகழ்வுகள், மொத்த தள வருவாய் போன்ற அளவுகோல்களைப் பார்க்கலாம்.
- **நிகழ்வு மதிப்பாய்வு**: அனைத்து ஏற்பாட்டாளர்களின் நிகழ்வுகளையும் ஆய்வு செய்து, நிர்வாகத் திருத்தம் மற்றும் நீக்குதல் செயல்களைச் செய்யலாம்.
- **பயனர் தணிக்கை**: கணக்குப் பதிவுகளைக் கண்காணித்து, தளத்தில் வழங்கப்பட்டுள்ள பயனர் பங்குகளைச் சரிபார்க்கலாம்.

## அமைப்புக் குறிப்புகள்

சூழல் மாறிகள் (environment variables) மூலம் அமைப்புகள் நிர்வகிக்கப்படுகின்றன. திட்டத்தின் root கோப்பகத்தில் அல்லது `eventpro-rs/` உள்ளே `.env.example` கோப்பை `.env` என நகலெடுக்கவும்:

```bash
cp .env.example .env
```

| மாறி | தேவையா? | இயல்புநிலை | பயன்பாடு |
| :--- | :--- | :--- | :--- |
| `DATABASE_URL` | கட்டாயம் (அல்லது தனித்தனி `DB_*` மாறிகள்) | இல்லை | MySQL இணைப்பு சரம்: `mysql://user:pass@host:port/database` |
| `SESSION_SECRET` | கட்டாயம் | இல்லை | அமர்வு கையொப்பத்திற்கான இரகசிய விசை (குறைந்தது 16 எழுத்துகள்) |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | மாற்று வழி | இல்லை | `DATABASE_URL` அமைக்கப்படாதபோது பயன்படுத்தப்படும் தனித்தனி இணைப்பு அளவுருக்கள் |
| `PORT` | விருப்பம் | `3001` | Axum HTTP சேவையகம் கேட்கும் துறைமுகம் |
| `HOST` | விருப்பம் | `127.0.0.1` | சேவையகம் பிணைக்கப்படும் பிணைய இடைமுகம் |
| `APP_ENV` | விருப்பம் | `development` | `production` என அமைத்தால் அமர்வு cookie-களில் `Secure=true` அமல்படுத்தப்படும் |
| `PUBLIC_DIR` | விருப்பம் | `public` | CSS, கிளையன்ட் JavaScript, நிலையான ஊடகங்கள் உள்ள கோப்பகம் |
| `UPLOAD_DIR` | விருப்பம் | `PUBLIC_DIR/uploads` | பதிவேற்றப்படும் பேனர் படங்கள் சேமிக்கப்படும் கோப்பகப் பாதை |

*பாதுகாப்புக் குறிப்பு: Rust அமைப்பு ஏற்றியின் தனிப்பயன் debug formatter, `DATABASE_URL` மற்றும் `SESSION_SECRET` ஆகியவற்றை `[REDACTED]` என மறைக்கிறது. இரகசிய மதிப்புகள் standard output-லோ log சேகரிப்பு அமைப்புகளிலோ வெளியிடப்படுவதில்லை.*

## தொடங்குவது எப்படி

### 1. முன்தேவைகள்
- **MySQL Server 8.0+** — `3306` துறைமுகத்தில் இயங்க வேண்டும்.
- **Rust Toolchain 1.80+** — Cargo மற்றும் rustc உடன்.
- **Node.js 20+** — விருப்பமானது; `benchmarks/` உள்ள தனித்த benchmark suite-ஐ இயக்குவதற்கு மட்டும் தேவை.

### 2. தரவுத்தள அமைப்பு
உங்களுக்கு விருப்பமான MySQL client-ஐப் பயன்படுத்தி தரவுத்தள அமைப்பையும் மாதிரித் தரவையும் தொடங்கவும்:

```bash
# அட்டவணைகள் மற்றும் கட்டுப்பாடுகளை உருவாக்கும் schema-ஐப் பயன்படுத்தவும்
mysql -u root -p < database/schema.sql

# ஆரம்ப வகைகள், மாதிரி நிகழ்வுகள், இருக்கை வகைகள், மற்றும் demo கணக்குகளை ஏற்றவும்
mysql -u root -p event_lifecycle < database/seed.sql
```

சேவையகம் தொடங்கும்போது, அமர்வு மேலாண்மைக்கான `tower_sessions` அட்டவணை இல்லாவிட்டால் Rust பின்தளம் தானாக உருவாக்கும். மையப் பயன்பாட்டு அட்டவணைகளான `users`, `events`, `categories`, `seat_types`, `bookings`, `tickets` ஆகியவை மாற்றப்படுவதில்லை.

### 3. Rust பின்தளத்தை இயக்குதல்

களஞ்சியத்தின் root கோப்பகத்திலிருந்து:

```bash
cd eventpro-rs
cargo run
```

சேவையகம் தொகுக்கப்பட்டு, MySQL-உடன் இணைந்து, அமர்வு சேமிப்பைச் சரிபார்த்து, `http://localhost:3001` முகவரியில் (அல்லது நீங்கள் அமைத்த `PORT`-இல்) கேட்கத் தொடங்கும்.

செயல்பாட்டு நிலைச் சோதனைகள்:
- **சேவை உயிருடன் உள்ளதா (Liveness)**: `GET http://localhost:3001/health` — JSON நிலையை வழங்கும்.
- **சேவை தயாராக உள்ளதா (Readiness)**: `GET http://localhost:3001/ready` — நேரடி MySQL query-ஐச் சோதிக்கும்.

## பாதுகாப்பு மற்றும் ஒரேநேரச் செயல்பாட்டுக் கட்டமைப்பு

### 1. CSRF பாதுகாப்புடன் கூடிய POST Logout

அமர்வை அழிப்பது சரியான CSRF token கொண்ட `POST /auth/logout` கோரிக்கைக்கு மட்டுமே அனுமதிக்கப்படுகிறது. மேல் வழிசெலுத்தல் பட்டியும் டாஷ்போர்டு பக்கப்பட்டியும் `csrf_token` என்ற மறைக்கப்பட்ட புலத்தைக் கொண்ட semantic form-களை வழங்குகின்றன.
- சரியான token உடன் logout form சமர்ப்பிக்கப்பட்டால், MySQL-இல் அமர்வு அழிக்கப்பட்டு, பயனர் பொது முகப்புப் பக்கத்துக்கு திருப்பப்படுவார்.
- CSRF token இல்லாத அல்லது போலியாக உருவாக்கப்பட்ட token கொண்ட கோரிக்கைகள் HTTP 403 Forbidden என நிராகரிக்கப்படும்; பயனரின் தற்போதைய அமர்வு தொடர்ந்து அங்கீகரிக்கப்பட்ட நிலையிலேயே இருக்கும்.
- `GET /auth/logout` அணுகல் முயற்சிகளுக்கு HTTP 405 Method Not Allowed வழங்கப்படும். இதனால் web crawler-கள், link pre-fetcher-கள் அல்லது browser history வழிசெலுத்தல் காரணமாக அமர்வு தற்செயலாக முடிவடைவது தடுக்கப்படுகிறது.

### 2. Session Fixation தடுப்பு

ஒவ்வொரு வெற்றிகரமான உள்நுழைவு மற்றும் கணக்குப் பதிவுக்குப் பிறகும், பயனர் விவரங்களை அமர்வில் சேமிப்பதற்கு உடனடியாக முன் `session.cycle_id()` அழைக்கப்படுகிறது. இது புதிய session key-ஐ உருவாக்கி session fixation பாதிப்புகளைத் தடுக்கிறது.

### 3. ஒரேநேரக் கட்டுப்பாடும் பரிவர்த்தனை ஒருமைப்பாடும்

அதிக தேவை உள்ள டிக்கெட் விற்பனையில், பல பங்கேற்பாளர்கள் ஒரே நேரத்தில் கடைசி இருக்கைகளை முன்பதிவு செய்யும்போது race condition-கள் உருவாகலாம்:
- **Pessimistic Locking**: முன்பதிவு handler ஒரு transaction-ஐத் தொடங்கி, நிகழ்வு வரிசைக்கும் தேர்ந்தெடுக்கப்பட்ட இருக்கை வகை வரிசைக்கும் `SELECT ... FOR UPDATE` lock-ஐப் பயன்படுத்துகிறது.
- **கடுமையான திறன் சரிபார்ப்புகள்**: திறன் சரிபார்ப்பு பூட்டப்பட்ட transaction-க்குள் நடைபெறும். கோரப்பட்ட டிக்கெட்டுகள் கிடைக்கும் இருக்கைகளை மீறினால், பகுதி பதிவுகள் இல்லாமல் transaction rollback செய்யப்படும்.
- **இருக்கை வகை ஒருமைப்பாடு**: ஒரு நிகழ்வில் இருக்கை வகைகள் வரையறுக்கப்பட்டிருந்தால், சரியான வகையைத் தேர்ந்தெடுக்காத முன்பதிவுகள் ஒதுக்கீட்டுக்கு முன்பே நிராகரிக்கப்படும்.
- **அணு-பண்புடைய ரத்து**: முன்பதிவை ரத்து செய்யும்போது, booking பதிவை மாற்றுவதும் நிகழ்வு மற்றும் இருக்கை வகையின் திறனை மீட்டெடுப்பதும் ஒரே transaction எல்லைக்குள் நடைபெறும்.
- **மோதல் மீண்டும் முயற்சி**: தனித்துவமான டிக்கெட் குறியீடுகள் (`EVT-{event_id}-BKG-{booking_id}-{random_hex}`) uniqueness constraint-களுக்கு எதிராகச் சரிபார்க்கப்பட்டு, தேவையானால் தானாக மீண்டும் முயற்சிக்கப்படும்.

### 4. வரம்பிடப்பட்ட Multipart பதிவேற்றமும் கோப்பு முறைமைப் பாதுகாப்பும்

நிகழ்வு பேனர் பதிவேற்றங்கள் தனிமைப்படுத்தப்பட்ட streaming parser மூலம் கடுமையான வரம்புகளுடன் கையாளப்படுகின்றன:
- **கோரிக்கை உடல் வரம்பு**: நிகழ்வு உருவாக்கம் மற்றும் திருத்த endpoint-களுக்கு மொத்தம் 8 MB கோரிக்கை வரம்பு (`MAX_EVENT_FORM_BODY_SIZE`) உண்டு. வரம்பற்ற கோரிக்கைகள் மூலம் சேவை மறுப்பு (DoS) ஏற்படும் அபாயம் குறைக்கப்படுகிறது.
- **கோப்பு அளவு வரம்பு**: பேனர் கோப்புகளின் அதிகபட்ச அளவு 5 MB (`MAX_BANNER_SIZE`). இந்த அளவு மீறப்பட்டால் streaming நிறுத்தப்பட்டு முறையாகப் பிழை வழங்கப்படும்.
- **உரைப் புல வரம்பு**: நினைவகச் சோர்வைத் தடுக்க, கோப்பல்லாத form புலங்கள் 64 KB (`MAX_TEXT_FIELD_SIZE`) வரை மட்டுமே அனுமதிக்கப்படும்.
- **Magic-byte உள்ளடக்கச் சோதனை**: கோப்புகள் JPEG, PNG, WebP, GIF ஆகியவற்றின் வழக்கமான magic-byte கையொப்பங்களுக்காக ஆய்வு செய்யப்படும். பயனர் வழங்கும் கோப்பு நீட்டிப்புகளும் MIME header-களும் நம்பகமானவை எனக் கருதப்படுவதில்லை.
- **பாதுகாப்பான கோப்புப் பெயர்கள்**: பதிவேற்றப்படும் கோப்புகளுக்கு குறியாக்கவியல் ரீதியாக சீரற்ற hexadecimal கோப்புப் பெயர்கள் (`event-{timestamp}-{hex}.{ext}`) வழங்கப்படும். `..`, `/`, `\` போன்ற path traversal வரிசைகள் இலக்கு கோப்பகத்தை மாற்ற முடியாது.
- **வாழ்க்கைச் சுழற்சி சுத்தம்**: பதிவேற்றத்திற்குப் பிறகு database insert தோல்வியடைந்தால், தனியாக மீந்த படக் கோப்பு உடனடியாக நீக்கப்படும். நிகழ்வு நீக்கப்படும்போது அதன் தனிப்பயன் பேனர் நீக்கப்படும்; இயல்புநிலை seed asset-களான `event-*.jpg` பாதுகாக்கப்படும்.
- **Content sniffing பாதுகாப்பு**: பதிவேற்றிய கோப்புகள் `X-Content-Type-Options: nosniff` header உடன் வழங்கப்படும். இதனால் மறைக்கப்பட்ட HTML அல்லது script உள்ளடக்கங்களை browser செயல்படுத்துவதைத் தடுக்க உதவுகிறது.

### 5. போலி கட்டணச் செயல்முறை

Checkout திரை (`GET /bookings/payment`) மற்றும் உறுதிப்படுத்தும் endpoint (`POST /bookings/confirm`) ஆகியவை e-commerce checkout-ஐ மாதிரியாக்குகின்றன. Stripe அல்லது PayPal போன்ற வெளிப்புற கட்டணச் சேவைகள் அழைக்கப்படுவதில்லை. உறுதிசெய்யப்பட்ட முன்பதிவுகளுக்கு தள விளக்கத்திற்காக உடனடியாகச் செல்லுபடியாகும் ticket code-கள் வழங்கப்படும்.

## வெளியீட்டுக் கருத்துகள்

### Production வெளியீட்டு குறிப்புகள்
1. **Reverse Proxy அமைப்பு**: Production சூழலில் EventPro-ஐ Nginx, Caddy அல்லது cloud load balancer பின்னால் இயக்கி, TLS முடித்த பின் போக்குவரத்தை `127.0.0.1:3001`-க்கு அனுப்பவும்.
2. **Cookie பாதுகாப்பு**: `APP_ENV=production` என அமைக்கவும்; இதனால் session அடுக்கு cookie-களுக்கு `Secure=true` மற்றும் `SameSite=Lax` அமைப்புகளைப் பயன்படுத்தும்.
3. **நிலையான பதிவேற்றச் சேமிப்பகம்**: Container சூழல்களில் (Docker அல்லது Kubernetes), பதிவேற்றப்பட்ட ஊடகங்கள் pod மறுதொடக்கத்திற்குப் பின்னும் நிலைத்திருக்க `UPLOAD_DIR`-ஐ நிரந்தர shared volume-க்கு இணைக்கவும்.
4. **கிடைமட்ட விரிவாக்கம்**: தரவுத்தளத்தில் சேமிக்கப்படும் `tower_sessions` அட்டவணையால், sticky session தேவைப்படாமல் round-robin load balancer பின்னால் பல backend instance-களை இயக்க முடியும்.

```text
└── README.md                 <- திட்ட ஆவணங்களின் தொகுப்பு
```

## சோதனை மற்றும் சரிபார்ப்பு நடைமுறை

Rust codebase-ல் unit test-கள், template rendering, மற்றும் database integration ஆகியவற்றுக்கான விரிவான சோதனைகள் உள்ளன.

சரிபார்ப்பு தொகுப்பை இயக்க `eventpro-rs/` கோப்பகத்திற்குச் செல்லவும்:

```bash
cd eventpro-rs

# 1. Formatting சரிபார்ப்பு
cargo fmt --check

# 2. கடுமையான linter சரிபார்ப்பு
cargo clippy --all-targets -- -D warnings

# 3. வழக்கமான test இயக்கம்
cargo test

# 4. உண்மையான MySQL தரவுத்தள integration suite (97 tests)
# Linux / macOS:
STRICT_DB_TESTS=1 cargo test -j 2

# Windows PowerShell:
& { $env:STRICT_DB_TESTS='1'; cargo test -j 2 }
```

### கடுமையான தரவுத்தளச் சோதனை உத்தரவாதம்

`STRICT_DB_TESTS=1` எனக் குறிப்பிட்டால்:
- சோதனைகள் `3306` துறைமுகத்தில் இயங்கும் நேரடி MySQL instance-உடன் இணையும்.
- தரவுத்தளத்தை அணுக முடியாவிட்டாலோ அமைப்பு தவறாக இருந்தாலோ, integration சோதனைகளை அமைதியாகத் தவிர்ப்பதற்குப் பதிலாக suite உடனடியாக panic ஏற்படுத்தி நிற்கும்.
- உண்மையான transaction-கள், ஒரேநேர முன்பதிவு simulation, ticket code மோதல் மீண்டும் முயற்சிகள், பேனர் கோப்பு சேமிப்பு வாழ்க்கைச் சுழற்சிகள் ஆகியவை MySQL-ஐப் பயன்படுத்தி நேரடியாகச் சோதிக்கப்படும்.
